首次启动

第一次使用，只做这 6 件事

服务器配置只需完成一次。客户端加密密码不会保存，因此每次重启都要输入，这正是数据安全边界。

打开 Obsidian，输入客户端加密密码

启动窗口会自动出现。它用于在本机内存中解锁数据，关闭 Obsidian 后立即失效。

完成标准：右侧显示“同步完成”，而不是“已锁定”。

若是新设备，点击“开始配置”

填写服务器主机名、TCP 端口、SHA-256 指纹、服务器访问密码和设备名称。先点“测试连接”，成功后再“保存并连接”。

完成标准：测试提示服务器可达、指纹和访问密码均通过验证。

点击“初始化学习空间”

系统只创建缺失的文件夹与模板，不覆盖已有笔记。

完成标准：出现 10-Topics、20-Nodes、60-Cards、70-Maps 等目录。

打开“新建”→“学习主题”

主题名称写最终目标；已有计划时把 Markdown 大纲直接粘贴进去。

完成标准：知识树出现主题和节点，第一条未完成任务被标为“当前”。

点击“继续当前节点”

只处理当前一个问题。不要同时在多个节点中无序添加材料。

完成标准：当前节点中至少填写“当前理解”和“待探索”。

点击“立即同步”

正常情况下保存后会自动同步；第一次仍建议手动确认一次。

完成标准：状态回到“同步完成”，没有待处理提示。

表达工具

Markdown 语法：什么情况下用什么

Markdown 的目的不是排版炫技，而是让知识结构可以搜索、链接、生成树、交给 AI，并在任何设备上长期读取。

标题

# 是整篇标题；## 是固定学习章节；### 用于章节内的一个案例或子论点。不要跳级。

# 主题标题
## 当前理解
### 一个具体例子

普通段落与强调

连续论证用段落；**粗体** 只标结论或关键词；*斜体* 标术语、变量或轻微强调。

HTTP 是一种应用层协议。

**关键结论：** 请求重试必须考虑幂等性。
*idempotent* 表示重复执行结果不继续变化。

无序列表

并列事实、选项、特征，且顺序不影响含义时使用。不要用它替代完整论证。

- 优点：容易缓存
- 限制：可能出现陈旧数据
- 证据：见官方缓存规范

有序列表

算法、操作手册、实验和故障恢复步骤必须用有序列表，因为顺序会影响结果。

1. 保存当前配置。
2. 运行测试。
3. 检查退出码。
4. 失败时执行回滚。

任务列表

只表示可验证的动作。主题大纲中的任务会转换成学习节点；完成后用 [x]。

- [ ] 写出当前理解
- [ ] 完成最小实验
- [x] 找到官方定义

专项路线 A

英文学习：从语境到主动输出

不要把单词变成孤立的中英对照。Learning Loop 把术语、原句、技术含义、挖空、造句与复习连成一个循环。

在真实材料中遇到词

保留前后句和来源。优先记录影响理解或会反复使用的词，不追求把所有生词都收集。

完成标准：知道它在当前语境中承担什么含义。

“新建”→“英文词汇”

填写技术含义、多领域含义、原句、挖空、例句、自己的造句和易混词。

完成标准：不看翻译能根据上下文解释。

连接概念节点

如果术语对应一个技术概念，用内部链接连接到知识节点；词汇笔记解决语言，概念节点解决原理。

完成标准：英文术语与技术理解不是两份孤岛。

创建两类复习卡

一张考“语境→含义”，一张考“含义→自己造句”。不要把长词典释义放在答案中。

完成标准：答案能在 20 秒内说出并判定。

输出与纠错

用该词解释当前技术节点，或让 AI 只纠正表达与搭配；把纠正写进“易混词/修正记录”。

完成标准：一周后能在新句子中自然使用。
## 单词或术语
eventual consistency

## 技术含义
在没有新更新后，所有副本最终收敛到同一状态。

## 原句
The system provides eventual consistency under network partitions.

## 原句挖空
The system provides ______ ______ under network partitions.

## 自己造句
Our cache is eventually consistent, so a recent write may not be visible immediately.

## 易混词
- strong consistency：每次读取都满足更强的一致性保证
- causal consistency：保留因果相关操作的顺序
专项路线 B

编程学习：结论必须能运行

编程节点的证据不是“文章说了”，而是可复现的代码、测试、日志、性能数据和失败边界。

?

问题节点

示例：“为什么这个异步函数会重复提交？”而不是“学习 JavaScript”。

⌘

最小实验

删去无关依赖，只保留能产生现象的代码。记录版本、命令、输入和输出。

✓

自动验证

把理解变成测试；修复前测试失败，修复后测试通过，边界用额外用例固定。

先写预测

在“当前理解”写程序会如何运行、为什么。没有预测，运行结果只会变成新的抄录。

建立最小可复现示例

代码块注明语言；命令、版本、环境放在“实验或证据”。敏感信息只写密码管理器引用。

运行并保留输出

输出用代码块；长日志只保留关键片段并附原始文件链接。失败也属于证据。

解释差异

比较预测与结果，把错误模型写入“修正记录”，不要覆盖掉旧理解。

写测试与反例

至少一个正常用例、一个边界用例、一个失败用例。性能结论必须包含测量方法。

迁移到新问题

关闭笔记后重新实现，或把相同原理用于另一语言/框架；这一步通过后才能标记掌握。

## 当前理解
我预测重复提交来自按钮事件和重试逻辑同时调用 `save()`。

## 实验或证据
环境：Node.js 24，Windows 11

```powershell
pnpm test -- duplicate-submit.test.ts
```

实际：修复前调用 2 次；增加幂等键后调用 1 次。

## 边界条件
- 网络响应丢失时，客户端仍可能重试。
- 服务端必须持久化幂等键，进程内 Map 不足以保证。

## 修正记录
最初认为“禁用按钮”足够；实验说明它不能覆盖网络重试。
专项路线 C

论文学习：区分作者说了什么与证据支持什么

论文不是从摘要抄到笔记。先定位研究问题，再追踪方法、实验、结果、局限，最后提炼成可验证的知识节点。

“新建”→“论文笔记”

填写题目、作者、年份、链接、版本。先读摘要、图表、结论，写下论文试图解决的问题。

拆解方法与假设

方法解决哪一部分问题？依赖什么前提？哪些变量被控制，哪些没有？

逐图读取实验

每张关键图写“横轴、纵轴、对照、结果、能否支持断言”。统计显著不等于实际重要。

分离四种内容

原文短摘、自己的翻译、自己的理解、自己的质疑分别进入对应章节，绝不混写。

提炼知识节点

把可迁移结论变成节点，把术语变成英文笔记，把可检验命题变成编程或数据实验。

复现或反驳

能运行代码就复现最小结果；不能运行时至少检查数据、实验设计和替代解释。

章节必须回答的问题完成证据
研究问题现有方法哪里不足？论文具体解决什么？能用两句话说明输入、目标和约束
方法核心机制是什么？依赖哪些假设？能画出流程或伪代码
实验对照是否公平？指标是否回答研究问题？逐图解释变量和结果
结果数据真正支持到哪一步？区分数值结果和作者解释
局限换数据、规模、硬件或分布后还成立吗？至少一个反例或待验证边界
提炼哪些知识能迁移到自己的项目？节点、实验或复习卡已创建并链接
交互学习

英文、编程、论文不是三套系统

它们通过主题、节点、来源、实验、术语与复习卡互相转化，最终只形成一棵知识树。

推荐交互链论文提出一个机制 → 提炼为知识节点 → 记录关键英文术语 → 编写最小实验 → 用结果修正节点 → 把定义、边界和诊断步骤做成复习卡 → 在新项目中迁移。
AI 协作

让 AI 看见你的目标、知识树与证据

点击“复制给 AI”会生成结构化上下文：目标、进度、知识树、当前节点、相关节点摘要和建议的教学方式。疑似凭据内容会被自动省略。

适合交给 AI

  • 用问题检查理解
  • 寻找反例和边界
  • 设计最小实验
  • 比较两种解释
  • 把长材料拆成节点
  • 生成候选复习题，再由你核对

不要直接交给 AI

  • 服务器密码、客户端密码
  • 私钥、令牌、Cookie
  • 未脱敏的客户或个人数据
  • 无法核实却要直接写成结论的内容
  • 让 AI 替你判断“已经掌握”
我会粘贴 Learning Loop 生成的上下文。请严格按以下顺序：

1. 先用 3—5 个问题检查我的当前理解，不要立即讲答案。

发送前最后检查自动检测只能识别“看起来像凭据”的文本，不能理解所有隐私。粘贴给任何 AI 前，仍要人工浏览一次上下文。

已掌握不看笔记能解释、应用、识别反例复述、重做、迁移任务、回顾表现进入间隔复习

不会

想不起来或核心模型错误。看答案后写一句错误原因，尽快再次复习。

模糊

方向正确但遗漏条件、步骤或术语。补一个最小提示，不要把答案越写越长。

掌握

完整、准确、在合理时间内回答，并能解释边界。系统延长复习间隔。

安全与连续性

同步、密码与恢复

⌁

服务器配置

主机名、端口、指纹、设备名会持久化。服务器访问密码保存在 Obsidian SecretStorage，不写入 Markdown。

🔒

客户端加密密码

永不保存、永不上传，只在当前进程内存中派生解密密钥。丢失后无法恢复加密数据。

⇅

自动同步

文件变化会进入队列；解锁后自动同步，桌面端后台周期同步，失败的上传可以续传。

⚠

冲突保护

无法安全合并时保留冲突副本，不用“最后写入覆盖”静默丢失内容。解决后再删除冲突文件。

必须备份客户端密码用可信密码管理器保存；不要写入 Obsidian、截图、聊天或服务器日志。服务器访问密码与客户端加密密码必须不同。
持续节奏

每天 45 分钟、每周一次整理

每日会话

  1. 解锁并确认“同步完成”。
  2. 打开“今日”，完成到期回顾（5—10 分钟）。
  3. “继续当前节点”，先写已有理解（5 分钟）。
  4. 阅读/实验并记录证据（20—25 分钟）。
  5. 写修正、边界和下一问题（5 分钟）。
  6. 创建 1—3 张关键复习卡，确认同步。

每周整理

  1. 打开知识树，处理孤立或过大的节点。
  2. 检查所有“待核实”和“确信度低”。
  3. 把资料/论文中的结论提炼成节点。
  4. 合并重复节点，补内部链接和来源。
  5. 重新生成主题图谱，检查跨领域关系。
  6. 选择下周唯一的主主题与当前节点。
问题排查

看到异常时按顺序处理

一直显示“已锁定”
  1. 点击“解锁”。
  2. 输入首次创建加密空间时使用的同一个客户端密码。
  3. 不要输入服务器访问密码。
  4. 如果确实丢失客户端密码，加密内容无法恢复；这是端到端加密的安全保证。
服务器明明在线，但同步不可用
  1. 打开“同步与安全”→“修改配置”。
  2. 点击“测试连接”。
  3. 按提示分别检查主机名/端口、SHA-256 指纹、服务器访问密码。
  4. 测试成功后点击“保存并连接”，再输入客户端密码。
创建主题后没有节点
  1. 确认大纲至少有一个 Markdown 标题或任务。
  2. 推荐用 ## 阶段 与 - [ ] 任务。
  3. 打开主题，执行“把 Markdown 大纲导入当前主题”。
  4. 如果仍失败，保留主题文件并查看通知，不要反复创建同名主题。
同步出现冲突文件
  1. 打开 00-Inbox/Sync Conflicts。
  2. 比较冲突副本与正式文件，不要直接删除。
  3. 把需要的内容合并回正式笔记。
  4. 确认同步完成后再删除已处理的冲突副本。
界面太专注，想临时使用 Obsidian 原生工具

设置 → Learning Loop → 关闭“专注模式”，或命令面板执行“Learning Loop：切换 Learning Loop 专注模式”。再次开启即可恢复本手册中的界面。

AI 上下文提示内容被省略

该节点包含疑似密码、私钥、令牌或 API key。先把秘密移到密码管理器，只在笔记中保留条目名称，然后重新复制上下文。

最后一条规则

不要追求笔记数量，追求可解释的变化

一个完整学习会话的最小成果你修正了一个错误理解、增加了一条可复查证据、明确了一个边界，或在新场景中成功使用了一个原理。做到其中之一，就比创建十篇空模板更有价值。
